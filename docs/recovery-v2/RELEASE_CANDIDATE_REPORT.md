Локальный кандидат: ветка `integration/evgeny-transfer-2026-10-19`; последний зафиксированный перед политикой коммит `4534a65`, точный release SHA сверять с `git rev-parse HEAD`. **На production не развёрнут.** Feature freeze введён после PDF, музыкального трейлера и исправления мобильной подписи. Новые функции, художественные итерации и переработка расчётов остановлены; допустимы только исправления критических дефектов и подготовка безопасного деплоя.

Публичный URL, указанный в production-конфигурации: `https://robodovod.ru`. Его текущая версия и доступность не подтверждены: запрос `/health` из этой среды завершился тайм-аутом. В репозитории нет `.env.production` и проверенного SSH-доступа/сведений о состоянии действующего сервера. Заказчик сообщил, что выполнит деплой сам по [инструкции](SELF_DEPLOY_RC.md) и перенесёт локальный Git bundle. Обычный push не прошёл из-за отсутствия учётных данных; повышенный push отклонён автоматической проверкой как не подтверждённая передача в GitHub. После явного выбора заказчика push не повторялся. Production backup, restore drill, миграция, переключение трафика и smoke **не выполнены**.

## Музыка и статические файлы

Заказчик подтвердил право использовать «Dead morose WMD 2.wav» публично в текущей сессии. Исходный WAV 121 с, stereo, 44,1 кГц, 24-bit PCM хранится отдельно в `Разобрать/Dead morose WMD 2.wav` (SHA-256 `52EF3A28767A32DE56EEA26C6354513AFF55F0DCAD2C2A926CBDDF33EEBDF370`). Он не подключается к веб-странице. Сценарий `mux_trailer_music.py` добавляет AAC 48 кГц / stereo / 192 кбит/с к 60-секундным MP4, не перекодируя H.264. Плавное появление 0,5 с, затухание 2,8 с, скорость и тон неизменны. `ffprobe` и SHA manifest проверены; веб-MP4 ~7,0 МБ, master ~22,7 МБ. 18-секундный preview ~1,6 МБ остаётся немым и поддерживает reduced motion. Плеер запускает звук только после клика пользователя.

Frontend production build содержит `demo/trailer/robodovod-trailer-web-720p.mp4`, preview и `robcraft/index.html`. Локальный Vite отдаёт MP4, постер и VTT по HTTP 206 на Range запрос, а RobCraft HTML по 200. Production Nginx/Caddy отдача, Range и мобильный браузер на публичном домене ещё не проверены.

## Деплой и данные

`docker compose --env-file .env.production.example -f compose.yaml -f compose.production.yaml config --quiet` прошёл. Локальная PostgreSQL и Alembic head совпадают на `0014_picking_project_runs`; `capacity`/`discovery` ссылаются на `organizer-catalog-v4`. Это не свидетельство о production схеме. Локальный Docker daemon недоступен. На сервере перед изменениями нужно сверить текущий commit, контейнеры, Alembic revision и активный каталог; сделать backup PostgreSQL+uploads через `scripts/production/backup.sh`, проверить хеши и восстановление отдельной БД через `restore-drill.sh`. Применять миграцию и переключать трафик только после этой проверки по [production runbook](../PRODUCTION_DEPLOYMENT.md). Не запускать bootstrap/import/activation на существующей БД автоматически.

Откат: сохранить текущие образы и commit до выпуска; при дефекте вернуть трафик на проверенную совместимую версию. Если схема уже изменена несовместимо, сначала оценить roll-forward или восстановление из проверенного backup. Не использовать `docker compose down -v` и слепой Alembic downgrade.

## Ручная проверка после безопасного развёртывания

1. Открыть главную и три примера; проверить работы → роботы → симуляция, 2D/3D, паузу → деньги/«Что если?» → результат и PDF. Сверить, что сценарные допущения маркированы как сценарные.
2. Оператору сверить опубликованную политику с действующей инфраструктурой и уведомлением. Зарегистрировать тестового пользователя с новой версией согласия; проверить вход/выход, недоступность чужого проекта и CSRF.
3. В RobCraft поставить и удалить объекты, назначить зоны, запустить робота, сохранить и открыть проект.
4. На 360/390/768 px проверить кнопки, меню, чат, PDF и 2D/3D.
5. Включить музыкальный трейлер нажатием: звук, Mute/Unmute, громкость, перемотка шести глав. Проверить HTTP 200/206 статических MP4, browser console и логи backend/Caddy.
