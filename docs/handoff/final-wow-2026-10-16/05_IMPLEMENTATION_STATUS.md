# 5. Состояние реализации после консультации

Срез локального рабочего дерева от 17.10.2026. Скриншоты `new-*` сделаны с локальной production-сборки; развёрнутый сайт и полноценный проект с живой БД отдельно не проверялись. Плана реального склада и спецификации Евгения пока нет.

## Что работает

1. На главной есть анимированная схема и прямой вход в гостевое демо без анкеты. Два независимо сохранённых варианта одного авторского примера: 2 000 и 2 400 паллет/сутки, 18 и 22 робота. Для обоих есть свои симуляция, экономика, JSON и PDF.
2. Гостевое демо показывает выбор нагрузки, профиль MULE и 3D/2D перед финансовыми таблицами. Выбор робота для своего расчёта находится **до** запуска визуализации. В 2D можно выбрать конкретного робота; 3D-камера при переключении следует за ним при общем модельном времени.
3. Конструктор склада в основном маршруте принимает PNG/JPG/WebP как подложку, ASCII DXF с прямыми LINE/LWPOLYLINE после подтверждения единиц и слоёв, JSON ранее сохранённой схемы. Пользователь может нарисовать зоны, стеллажи, препятствия, запретные области, зарядку и точки передачи. DWG нужно экспортировать в DXF или изображение.
4. `facility-layout-v1` хранит размеры, объекты и происхождение (`DRAWN`, `PROVIDED`, `ASSUMED`). Локальная сеточная проверка учитывает ширину робота, 0,25 м зазора с каждой стороны, находит проходимый путь или показывает блокировку. План сверху и объёмный эскиз используют один набор объектов и один маршрут. Анимация показывает путь, без выдуманной скорости.
5. После явного применения длина маршрута становится входом **нового серверного расчёта**. Изменение плана сбрасывает это значение и ревизию ввода. После расчёта показывается схема и применённое расстояние, а отдельный серверный `facility-layout-evidence-v1` сохраняет неизменяемую версию плана с ID расчёта и контрольными суммами. Повторное открытие такого расчёта может восстановить эту схему. Два последовательных расчёта сравниваются по расстоянию, парку и мощности; интерфейс не приписывает всю разницу одному фактору без сверки остальных входов.
6. Учебная схема 72 × 48 м с функциональными зонами сгенерирована по открытым референсам. Это **авторский пример**, не план существующего склада. Открытие схемы показывает источники и специально заданное препятствие: путь 52 м против 46 м без него.
7. Условная 3D-сцена получила потолочные балки/свет, короткий общий план, сопровождение робота и возврат к обзору. Эти элементы декоративные и не входят в карту коллизий. 2D выделяет выбранного робота и путь. В гостевом примере визуальные координаты остаются условными.
8. Экран примера показывает разницу денежных потоков первого года с первоначальными вложениями, но существующая серверная метрика ROI **не переименована** до согласования формулы. Непросчитанные роли, включая комплектовщиков и фасовщиков, перечислены отдельно.

## Границы, которые нельзя скрывать на показе

- Для гостевых 2D/3D используется условная геометрия сохранённого сценария. Учебная схема конструктора **не привязана** к этим числам и не выдаётся за тот же склад.
- Для собственного объекта сервер получает из планировки только явно применённое **расстояние**. Сами препятствия пока не участвуют в серверной событийной симуляции, ожидании, очереди и коллизиях. Объёмный эскиз из плана не является верифицированной RobCraft-сценой.
- Серверный снимок схемы хранит геометрию, но не исходные байты изображения-подложки. Сохраните исходный файл отдельно. Фактический масштаб DXF подтверждает пользователь; мы не проводим инженерную экспертизу CAD.
- Нельзя достоверно пересчитать ROI после вычета вложений или включить новые роли в сводную экономику без договора о формулах и исходных данных Евгения. Эта часть плана остаётся открытой. Не распространять существующее NPV паллетной перевозки на весь склад.
- Для убедительной привязки к конкретному объекту нужен реальный план/обмер, параметры робота и проверка маршрута на площадке. Открытые референсы не заменяют эти данные.

## Проверки

- Frontend: 185 unit-тестов, ESLint по `src` и `tests`, сборка Vite.
- RobCraft: 117 unit-тестов.
- Backend: 28 тестов по новому контракту планировки и соседним контрактам ввода/складской цепочки.
- Локальный Chrome: `python scripts/browser_wow_demo.py` — оба гостевых варианта, 3D, 2D, мобильный конструктор, путь, объёмный вид, DXF. Кадры сохранены в `screenshots/`.

Новый API сохранения схемы проверен контрактными тестами; сквозной тест с авторизованным проектом и настоящей БД ещё нужен перед развёртыванием.
