# VISUAL POLISH V1 — локальный проход 20.10.2026

Основной ориентир: `Разобрать/ROBODOVOD_VISUAL_POLISH_V1/02_TARGET_REFERENCES/CONCEPT_02_PRIMARY_FULL.png`. Этот проход сохраняет накопленное рабочее дерево. Источник чисел — серверный `ReportViewModel`; проверка опубликованного каталога и PostgreSQL не проводилась.

## Реализовано

- Тёмные токены, фиолетовые CTA, hero главной, карточки трёх объектов, поверхности симуляции, «Что если?» и результата. Использованы текущий trailer poster и кадры runtime сцен, а не изображения концепта.
- 3D увеличен относительно 2D-плана на desktop. На mobile добавлен переключатель 3D/2D с одной видимой сценой. Обе проекции продолжают читать один `SceneModel`.
- В рендере склада добавлены визуальные полки и груз на существующих footprint стеллажей, изменены фон и материал пола. Декор не входит в коллизии и экономику.
- UI результата показывает KPI из `ReportViewModel`, длинная таблица работ становится карточками на узком экране.
- Ответ симуляции на устаревшие параметры и ответ после размонтирования компонента больше не применяются.
- PDF-таблицы переносят длинные ячейки и повторяют заголовок при переходе страницы; лишние принудительные переходы страниц убраны. Сырой числовой формат PDF сохранён ради существующего контракта точного извлекаемого значения.
- RobCraft получил более читаемые панели; устранено перекрытие панели и hotbar на 768 px.

## Открытые риски

- В локальном smoke каталог `ui-smoke` пуст: показанные неизвестные цены и нулевой парк корректны для stub, но не доказывают реальную воронку с опубликованным каталогом.
- `DATABASE_URL` отсутствует. Новые поля ScenePatch, audit согласия и production access не подтверждены на реальной PostgreSQL.
- PDF сохраняет исходные точные числовые строки для тестового контракта; оформление денежных сумм с пробелами-разделителями не доведено. На отдельных страницах остаётся низкая плотность текста.
- Референсные фотографии и высокодетальные модели не установлены. Демонстрационная геометрия явно подписана и не является обмером объекта.
- `privacy-policy.html` остаётся проектом без реквизитов оператора и требует юридического согласования перед публичной регистрацией.
