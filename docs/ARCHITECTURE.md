# Архитектура действующего прототипа

[Корневой README](../README.md) объясняет назначение и запуск. Эта схема показывает границы компонентов текущего checkout, а не целевую архитектуру из [планов](planning/README.md).

| Компонент | Ответственность |
| --- | --- |
| [frontend](../frontend/README.md) | React/Vite: гостевой пример, ввод проекта, каталог, результаты, PDF/ZIP, 2D и встроенная сцена RobCraft. |
| [backend](../backend/main.py) | FastAPI/Pydantic: маршруты, проверка входов и прав, расчёт, экспорт. `persistence_api.py` отвечает за проекты и сохранённые версии. |
| `backend/calculation/` | Нормализация процесса, проверка применимости, физический расчёт и денежные модули с явными входами. |
| `backend/catalog_*` | Импорт версионированного bundle, чтение опубликованного каталога и активация независимых слотов. |
| PostgreSQL + Alembic | Пользователи, проекты, исходные/результирующие снимки, активации и аудит. |
| [RobCraft](../robcraft/README.md) | Условная браузерная 3D-визуализация сценария. |
| Compose, Caddy | Локальный запуск и production overlay; Caddy публикует сайт и API в production. |

Поток нового проектного расчёта: ввод → нормализация → подтверждение профиля → выбор из одобренного `capacity` каталога → расчёт парка → явные денежные входы → сохранённый результат → 2D/3D и экспорт. `discovery` используется для просмотра каталога. Legacy маршруты читают отдельный `runtime`; в organizer bundle нет допустимых legacy-моделей. Economics route включается отдельно по утверждённому отчёту. Без нужной активации соответствующий расчёт недоступен; `/ready` проверяет только БД.

Сохранённые расчёты и файлы привязаны к владельцу. Изменение ввода создаёт новую версию; повторное открытие и экспорт читают снимок, не заменяя его текущими ценами или формулами. Изменяющие запросы требуют сессию и CSRF. Схемы маршрутов: [API](API.md); смысл показателей: [расчёты](CALCULATIONS.md).
