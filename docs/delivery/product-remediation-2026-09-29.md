## Этап 1

Панель состояний имеет постоянные строки, ограничение высоты и внутреннюю прокрутку;
текст длинного статуса доступен внутри карточки. Размер canvas и положение следующего блока
при смене статуса стабильны на desktop/mobile: смещение **0 px**.
Ожидание Brain ограничено 70 секундами при серверном пределе 59 секунд.
Запрос отменяется при уходе, поздний ответ не меняет другой проект,
повторный submit заблокирован синхронным guard. Polling читает сохранённый статус и во время POST;
после ошибки клиент читает сохранённый профиль. Клиентская отмена не объявляется отменой серверного turn.

Модель извлекает предложения из последнего сообщения с небольшим подтверждённым контекстом
и серверным следующим вопросом. Числовой ответ без единицы относится только к этому вопросу;
распознанное число остаётся неподтверждённым. Расчёт и следующий обязательный вопрос выбирает сервер.
Отсутствие конфигурации, HTTP 401/429, неправильный JSON и таймаут проверяются заглушками.

Доказательства: `.test-product-remediation/baseline-browser.json`,
`.test-product-remediation/stage1-browser.json`, снимки `layout-1366.png`, `layout-390.png`.
Прогон Chrome проверяет отсутствие смещения, один POST при двух submit и игнорирование позднего ответа
после смены проекта. Unit-проверки покрывают конечное ожидание и внешнюю отмену.

Production, push, отправка конкурсной формы и платные вызовы не выполняются.

## Этап 2

Полноэкранный мобильный dialog / большое окно desktop: финансовые вводные по группам,
точный ввод с ползунком, отдельные режимы FIXED/PERCENT внедрения и RaaS,
исходный вариант и preview для покупки и RaaS, таблица шести вариантов с недоступными показателями.
Физика привязана к сохранённому C11; окно не заявляет пересчёт мощности от изменения денег.
Частичные v6-результаты тоже открывают окно; старые версии переходят к заполнению нового ввода
через существующий редактор, без автоматического дополнения неизвестных значений.

Годовые потоки и накопленный эффект вычисляет сервер. Новый отдельный контракт
`economics-preview-charts-v1` содержит год 0 (CAPEX) и годовые значения.
Проверено, что конец накопленного эффекта совпадает с серверным net benefit.
Основной финансовый движок и допущения его действующей версии не заменялись.

Preview возвращает digest точного ввода, физическую привязку и исходный digest.
Сохранение проверяет ввод и исходную версию; повтор с тем же ключом возвращает тот же run.
Редактирование и повторный submit заблокированы на время сохранения.
Запоздалый preview, даже при транспорте, игнорирующем AbortSignal, не попадает в новый черновик.
После ошибки сохранения повтор использует прежний ключ. Отмена и повторное открытие сбрасывают черновик.

Дополнительно исправлено использование `checksums.result` из реального ответа API
и вывод процентного тарифа в PDF. PDF/CSV/XLSX v6 включают сохранённые финансовые входы,
их источники и предпосылки. PDF содержит run ID новой версии и digest результата.
Экспорт строится из сохранённого run.

Одноразовый PostgreSQL 17: новый кластер `.test-product-remediation/postgres`,
loopback `127.0.0.1:55439`, отдельные БД каждого прогона; существующие БД не использованы.
Интеграционная проверка подтверждает: preview не вставляет AnalysisRun,
все финансовые показатели совпадают при preview/save, повтор идемпотентен,
старые input/result/scenario snapshots и checksums неизменны, reopen сохраняет ввод,
PDF относится к новому run и содержит его показатели.
Артефакты: `.test-product-remediation/scenario-save-evidence.json`, `scenario-saved.pdf`,
`acceptance-browser.json` (быстрые правки, поздний ответ, сброс, процентный ноль,
