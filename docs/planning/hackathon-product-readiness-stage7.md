# Этап 7: сквозная приёмка и выпуск

Локальная приёмка 25 сентября 2026 года. Проверялась отдельная одноразовая PostgreSQL 16; исторические production `analysis_runs` и `simulation_artifacts` не изменялись. Новых миграций в этапах 1–7 нет.

## Результат приёмки

- Пустая БД прошла Alembic `base → head`. В ней импортирован официальный каталог: 223 позиции, 187 моделей, 189 медиафайлов; активированы discovery, capacity v2 и economics v2. Runtime-каталог не активировался.
- Backend на одноразовой PostgreSQL: **709 passed, 0 skipped**. В набор входят проверка неизменяемости и tenant isolation сохранённых runs, CSRF, прежнего C16 v1 и его snapshot replay, нового C16/C23 golden, строгих C23 digest/version/tenant guards, источников допущений и экспортных digest. Frontend: **111 passed**, lint и production build. RobCraft: **83 passed**. Отдельный Chrome smoke проверил точные байты PDF/ZIP на pinned golden.
- `scripts/browser_full_journey_smoke.py` прошёл в настоящем Chrome дважды, с первого экрана на **1366×768** и **390×844**. Проверены гостевое демо с шестью сохранёнными сценариями и честными C05/закупкой; регистрация, проект, 223 карточки каталога и изображения; поиск и сравнение помощника с источниками; подтверждённое интервью со своими числами; сохранённый C11 и частичный economics run с «не рассчитано»; полный C11 → C13–C21 с шестью сценариями → C23 → 2D и RobCraft; PDF/ZIP; reopen/replay. На узком экране у проверенных страниц нет горизонтального переполнения.
- PDF из браузерной загрузки побайтово совпал с ответом `report.pdf` для того же immutable run; его SHA-256 совпал с ответом API. `manifest.json` в ZIP совпал с авторизованным manifest endpoint, `X-Report-Source-Digest` — с digest исходного result snapshot. PDF содержит извлекаемый русский текст, ZIP прошёл CRC и содержит тот же PDF.
- Найден и исправлен разрыв собственного маршрута: форма скрывала обязательное для паллет поле «Единиц/рейс». Теперь пользователь вводит его явно перед C11. Никакие исторические снимки или формулы не изменялись.

## Короткий сценарий показа комиссии

1. Открыть главную. Нажать **«Попробовать демо»**: показать фиксированные 18 роботов, 137,45 ед./ч, 100 % покрытия и шесть сценариев покупки/RaaS. Открыть исходные допущения; пояснить `NEEDS_VALIDATION` и `UNVERIFIED`.
2. Вернуться на главную, нажать **«Рассчитать свой процесс»**. В интервью описать паллетные перевозки; показать предложения с исходной репликой, подтвердить поля и сравнить две карточки с источниками. Для сохранения зарегистрироваться и создать проект.
3. Внести собственные объём, график, плечо, зону, персонал и gross; перенести подтверждённый черновик в v2. В процессе явно указать **«Единиц/рейс»**, нормализовать ввод, выбрать модель, ввести время обмена и сохранить C11. Неизвестные коммерческие входы оставить пустыми и сохранить **частичный** результат: NPV должен остаться «не рассчитано», техническая 2D доступна при полном техническом графике.
4. Для полного числового примера открыть прямой складской маршрут, загрузить типовой склад, подтвердить допущения, сохранить C11. В экономике заполнить или предложить и отдельно подтвердить сценарные числа, сохранить шесть веток. Запустить C23 и показать синхронные 2D/RobCraft KPI. Открыть **«Мои проекты» → «Расчёты»**, повторно открыть run и скачать PDF/ZIP. Номер run и исходные digest должны совпасть.

Сценарий можно воспроизвести локально скриптом после запуска API, Vite и заполнения одноразовой БД. `STAGE8_MOBILE=1` запускает полный путь сразу на 390 px. Скрипт создаёт аккаунты и runs только в указанной локальной БД.

## Ограничения и состояние выпуска

Это предварительная оценка. Паспорт выбранной комплектации, фактические проходы/пол/нагрузка, доступность, цена, доставка, сервис и RaaS-договор требуют отдельной проверки. Демо-числа — сценарные допущения, не факты поставщика. Общие ресурсы нескольких зон автоматически не суммируются. C23 — модель, а не телеметрия или подтверждённый SLA.

На момент отчёта `origin/main` до публикации указывал на `8aaa0e73153e95900e855c8c992f3bca92a703d9`. Локальные gates зелёные. **Production-приёмка открыта:** SSH к `robodovod` на порт 22 завершился timeout, HTTPS `https://robodovod.ru/ready` также завершился timeout. Поэтому живые HEAD, Compose, `/ready` и пользовательский путь этим этапом не подтверждены. Серверные бекапы для выпуска не требуются.

После восстановления доступа команды с клиентского **Windows CMD** (каждая отдельной строкой). Сначала сверить, что server tree чистый и старый HEAD равен `8aaa0e73153e95900e855c8c992f3bca92a703d9`; при расхождении остановиться. После публикации `origin/main` сверить новый hash с hash коммита этапа 7:

```cmd
ssh robodovod "cd /opt/robodovod && git status --short && git rev-parse HEAD"
ssh robodovod "cd /opt/robodovod && git fetch origin main && git pull --ff-only origin main && git rev-parse HEAD"
ssh -tt robodovod "cd /opt/robodovod && sudo docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml config --quiet"
ssh -tt robodovod "cd /opt/robodovod && sudo docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml build backend frontend"
ssh -tt robodovod "cd /opt/robodovod && sudo docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml up -d --wait --no-deps backend frontend"
ssh -tt robodovod "cd /opt/robodovod && sudo docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml ps"
curl.exe -f https://robodovod.ru/ready
curl.exe -f https://robodovod.ru/api/catalog/status
```

Затем в обычном браузере по HTTPS пройти пункты 1–4, включая новый пользовательский проект, C11, частичный и полный результаты, C23, reopen и PDF/ZIP. Зафиксировать HEAD, Compose, ответы `/ready` и результат браузера **раздельно**. Если SSH/HTTPS недоступны или любой шаг не прошёл, не объявлять production готовым.

### Исправление после первого server build

При первом fast-forward сервер получил `1d72cfd`, но `docker compose build backend frontend`
остановился на сборке frontend: оба импорта `warehouse-economics-demo-v1.json`
не находили файл внутри build stage. Тот же файл нужен backend при импорте
`economics_partial.py`. Dockerfiles обоих сервисов теперь копируют только этот
версионированный JSON в `/data/scenarios/`; код расчёта и сохранённые runs не
изменялись. Локально успешно собраны оба Docker image, а исправленный backend
image импортировал `economics_partial` и `main`. На сервере после публикации
исправления нужно повторить `build backend frontend`, затем `up -d --wait
--no-deps backend frontend` и HTTPS-приёмку. Production готовность до этих
шагов не подтверждена.
