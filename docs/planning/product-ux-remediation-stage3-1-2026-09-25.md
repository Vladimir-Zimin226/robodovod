# Этап 3.1: разговорное моделирование процесса

## Что сделано локально

- Страница «Моделирование процесса» отделена от «Помощника по сервису». Диалог собирает версионированный профиль по схеме Brain v1.1: исходные слова, значение, единица, источник и подтверждение каждого поля. Следующий вопрос и готовность технической, трудовой, закупочной и арендной веток определяет сервер.
- Для диалога подключён серверный адаптер Yandex AI Studio с URI `gpt://<YC_FOLDER_ID>/deepseek-v4-flash`. Ответ проходит проверку схемой и серверной политикой; модель не сохраняет run и не исполняет формулы. Ключ остаётся на сервере. Ограничены контекст, частота, количество запросов/токенов и оценка расходов на проект. При ошибке модели текст сохраняется, явно названные локальным парсером данные остаются неподтверждёнными, доступны повтор сообщения и ручное исправление.
- Подтверждённый профиль адаптируется к действующим C03/C11, активному расчётному пулу каталога, экономике v2 и PDF/ZIP. Расчёт запускается только после preflight и выбора позиции. Неподтверждённые плечо, паллеты за рейс, число уборок и зарплата не попадают в ядро. Для 120 м, одной паллеты за рейс и одной уборки есть отдельные видимые предложения допущений. Пять коммерческих подтверждений обрабатываются существующей экономической формой.
- Изменение поля создаёт дочернюю версию профиля. Runs связываются с конкретной версией после проверки входов и принадлежности проекту. Предыдущие runs/PDF доступны по ссылкам; для нового C11 показаны изменённые входы и KPI относительно прошлого сохранённого C11 того же процесса. Несколько процессов сохраняются раздельно; неподдержанные операции остаются описанием без выдуманного парка или NPV.
- Ранее созданные immutable runs, их input/result snapshots и экспорт не изменялись.

## Проверки

- 7 unit tests Brain API: golden 220 паллет/сутки и 120 м, явное подтверждение, противоречивые единицы, отказ модели, несколько процессов, уборка и привязка run. Текущий код: `7 passed`.
- 2 integration tests на отдельной одноразовой PostgreSQL прошли до последних правок интерфейса и ответа `/runs`: права проекта/CSRF, версии и конфликт записи, недоступная модель, переключение процессов и лимит сообщений.
- До последних правок интерфейса полный браузерный путь в Chrome прошёл на 1366 и 390 px: собственные 220 паллет/сутки и 120 м → технический и частичный экономический результат/PDF → что если и новый PDF при сохранении старого; затем типовой склад с пятью подтверждениями → полный результат/PDF. При проверке сохранённых тестовых данных 7 из 7 C11 привязок соответствовали проверке входов; обнаружены 7 полных экономических runs.
- До последних правок 118 frontend tests и production build прошли. После исправления экрана Vite отдавал его с HTTP 200; затем по предупреждению браузерного журнала удалены дубли позиций каталога в селекторе. Unit tests backend, Ruff и `git diff --check` проходят.

## Открытые пункты приёмки

- Из этой среды соединение с Yandex AI Studio завершилось `ConnectTimeout`. Реальная доступность **DeepSeek V4 Flash** и поддержка `json_schema` именно этой моделью не подтверждены. Это обязательная проверка перед пилотом; локальный fallback не подтверждает работу модели.
- После последних правок повторные `npm test`, `npm run build` и браузерный сценарий не выполнены: Node в песочнице получает `EPERM` на чтение родительского пути, а автоматическая проверка запроса на запуск с повышенными правами отклонила его из-за лимита аккаунта до 26 сентября 2026, 00:43. Поэтому этап 3.1 нельзя считать полностью принятым, пока эти проверки не будут повторены на итоговом коде.
- Production выпуск в этот этап не входил. Этап 4 не начинался. Визуализация для нового диалога остаётся в бэклоге; открытие сохранённого технического результата в текущей 2D/3D сохранено.
- Отдельный коммит пока не создан: запись `.git/index.lock` запрещена текущей песочницей. Запрос на повышение прав для финальной браузерной проверки ранее отклонила автоматическая проверка из-за лимита аккаунта; обходить её нельзя. Все файлы этапа остаются в рабочем дереве.

## Конфигурация и пилот

Сервер использует `YC_API_KEY` и `YC_FOLDER_ID`; секреты не передаются браузеру. Для пилота нужно из серверной сети подтвердить ответ DeepSeek V4 Flash по структурированной схеме, затем пройти золотые диалоги и сравнить результат с прямым вызовом C11/экономики. Стоимость ограничена на проект кодом; рекламный баланс не используется как гарантия.
