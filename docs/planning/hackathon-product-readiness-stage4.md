# Этап 4: единый расчёт v2 и зоны процесса

Выполнено 25 сентября 2026 года по плану `hackathon-product-readiness-2026-09-25.md`.

- Новый пользовательский маршрут: объект → зона → процесс/роль → C11 → экономика и C23. Переключатели «Весь объект» и «По зонам», а также CTA для создания legacy run удалены из обычного интерфейса. Неподдержанный тип объекта обозначен явно. Исторические v1 URL и API сохранены; ранее созданный run открывается в отдельном режиме просмотра с точными сохранёнными значениями и PDF/ZIP экспортом.
- В черновике v2 есть основная зона; можно добавить, назвать и удалить другую зону. У каждой зоны собственные процессные входы: объём, график и маршрут. Ограничения сохраняются как неподтверждённая заметка. Одинаковая роль может обслуживать несколько процессов и зон, поэтому её численность и зарплата общие для черновика. При удалении зоны её идентификатор не переиспользуется в том же черновике.
- Для нового C11 введён `capacity-analysis-request-v3` с обязательным `capacity-zone-context-v1`; контекст привязан к идентификатору выбранного процесса и сохраняется в immutable input snapshot. Старый `capacity-analysis-request-v2` и его схема не менялись. В C11 передаются только выбранный процесс и относящиеся к нему роли; ссылки общей роли ограничиваются этим процессом. C23 получает тот же идентификатор зоны и задач, её название и предупреждение о непроверенных ограничениях. C05 от этого не повышается.
- Общие затраты площадки задаются одной группой полей для выбранного economics run. Расчёт парка и экономики остаётся отдельным для каждого процесса и зоны. Интерфейс прямо запрещает складывать парки или NPV отдельных runs при общих роботах, ролях, межзональных потоках и расходах. Автоматической сводки многозонного объекта нет; проверенный полный сценарий — одна зона типового склада.

Проверка: 99 профильных backend тестов; интеграционный PostgreSQL сценарий создал v3 C11, дочерний технический run и C23, проверил одинаковые zone/task ID, exact replay, reopen и сохранённый контекст зоны. Отдельный интеграционный прогон подтвердил неизменность старого run. Frontend: 107 тестов, lint и production build. Исторические snapshots и артефакты не изменялись; серверные бекапы не требовались.

Граница: C03 сохраняет идентификаторы зон в process ID, а название и ограничения фиксируются в C11 v3. Черновик до сохранения живёт в состоянии страницы. Из нескольких C11 нельзя вывести общий парк или общую экономику без модели разделяемых ресурсов и потоков; такой итог интерфейс не показывает.
