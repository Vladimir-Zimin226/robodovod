# Этап 2: демо склада и собственные экономические входы

Выполнено 25 сентября 2026 года по плану
`hackathon-product-readiness-2026-09-25.md`.

- Добавлен версионированный набор `warehouse-economics-demo-v1`: 16 условных чисел с единицами, датой, источником и объяснением. Значения взяты из проверочного расчётного сценария и не объявляются ценами, нормативами организаторов или предложением поставщика. Складской пример проверен на взаимную согласованность горизонта RaaS, gross сумм, явных нулей и полного расчёта шести сценариев.
- На первом экране разделены два входа: гостевой просмотр заранее рассчитанного склада без регистрации и отправки пользовательских данных; свой проект с ручным или файловым вводом. Гостевой пример показывает C11, baseline, покупку, RaaS, чувствительность и ограничения. Артефакт воспроизводится `python scripts/build_warehouse_guest_demo.py --check` из расчётных движков и тестового профиля модели.
- Форма экономики показывает отдельную полноту C11, труда, покупки, RaaS и входа визуализации. Для каждого числового поля можно выбрать пользовательский источник или сценарное допущение. Складской шаблон предлагает число, показывает происхождение и требует явного подтверждения. Пользовательское значение сохраняется при переключении источника; изменение числа снимает подтверждение; очистка оставляет неизвестное. Ноль, пустое поле и диапазон сохраняют разный смысл. Коммерческие подтверждения gross, цены, батареи и RaaS остаются отдельными действиями.
- Новый вход `economics-explicit-inputs-v3` сохраняет `field_sources` и `assumption_evidence` с версией, источником, датой, обоснованием, значением и подтверждением. Сервер сверяет шаблон с опубликованным набором и превращает неподтверждённое или подменённое число в неизвестное. Для других процессов складской шаблон отвергается. В базе создаётся новый immutable envelope `economics-run-input-v4`; результат остаётся совместимым с прежним контрактом. Редактор сохранённого результата создаёт новый дочерний run с `source_run_id`, а исходный run открывается и воспроизводится отдельно. PDF полного результата раскрывает подтверждённые допущения.
- Файловый путь переносит проверенные складские параметры в C11 v2 с provenance файла; отсутствующие партии и зарплаты остаются неизвестными. Старый `fte_cost_rub` не трактуется как gross зарплата. C05 `NEEDS_VALIDATION` и закупка `UNVERIFIED` не повышаются от выбора демо-чисел.

Проверка: 55 профильных backend tests; 44 tests PDF и частичной экономики; 104 frontend tests; lint и build; воспроизводимость гостевого артефакта. PostgreSQL integration test создания, повторного открытия, exact replay и нового дочернего run пройден дважды на одноразовых локальных базах. Сохранённые исходные SHA-256 остались прежними. Production и исторические immutable runs не менялись.

Границы: гостевое демо является статическим проверочным примером с синтетическим тестовым профилем модели; собственный проект использует активный каталог и может дать частичный результат. 2D/C23 для нового C11 или частичной экономики относится к этапу 3. Коммерческие условия и применимость решения требуют отдельной проверки.
