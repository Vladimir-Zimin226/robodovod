# Этап 5: помощник по каталогу и внешний поиск

## Реализация

- Страница «Процесс» теперь ведёт диалог: ищет в активном discovery-каталоге, задаёт следующий вопрос, показывает 2–3 позиции в таблице с одинаковыми критериями и открывает исходную карточку. Поиск строит корпус из снимка активной версии при каждом запросе; смена активации сразу меняет версию и состав ответов. Для 223 позиций отдельный хранимый индекс и миграция БД не нужны.
- Корпус содержит название, изготовителя, тип, исходное назначение/описание, явно записанные ограничения, **только** характеристики из `matching_spec_facts`, статус участия в capacity, ссылку на карточку, строку источника и страницу официального PDF там, где импортировано изображение. Дата в ответе — `observed_at` исходного артефакта, а не дата изготовления робота. Непроверенное enrichment и цена из карточки в ответы/сравнение не попадают. Пустое поле называется отсутствующим; подходящая запись не означает пригодность к закупке.
- Вопросы и черновик полей формируются детерминированно из ограниченной истории. Черновик не сохранён и не подтверждён; отдельная кнопка подтверждения лишь открывает форму расчёта с предварительно заполненными полями и provenance `USER`. Сам расчёт и сохранение run остаются отдельными действиями пользователя. Переписка хранится только в памяти приложения в границах текущего пользователя/проекта и сохраняется при переходе в карточку и обратно.
- «Найти в интернете» — отдельный запрос Yandex Search API от вошедшего пользователя с CSRF. Сервер использует существующие `YC_API_KEY`/`YC_FOLDER_ID`, возвращает до пяти ссылок с датой поиска и коротким фрагментом. Внешний текст отображается как данные; страницы не загружаются сервером и не поступают в каталожный поиск, расчёт, цену или eligibility. XML с DTD/entity отклоняется; ссылки ограничены HTTP(S). При отказе Yandex выводится понятное сообщение, каталог продолжает работать. Ключ не включается в ответ или журнал.
- Лимиты приложения: сообщение каталога до 400 символов и шести реплик истории, веб-запрос до 300 символов, тайм-аут провайдера 8 секунд, 60 каталожных запросов на IP и 5 платных веб-запросов на пользователя за минуту в одном процессе. Проектный запрос проверяет владельца; чужой проект получает 404. Веб-запрос требует авторизации и CSRF.

## Проверка доступов, квот и стоимости

Проверены официальные документы Yandex Cloud на 25.09.2026: для Search API нужен `search-api.webSearch.user` и ключ со scope `yc.search-api.execute` ([права](https://yandex.cloud/en/docs/iam/roles-reference), [пример настроек](https://aistudio.yandex.ru/en/docs/search-api/operations/smart-snippets)). REST-запрос — `POST /v2/web/search` с `folderId`, ответ XML приходит как Base64 `rawData` ([спецификация](https://aistudio.yandex.ru/en/docs/search-api/api-ref/WebSearch/search)). Документированные квоты синхронного поиска — 10 запросов/с и 10 000/час, предел запроса — 400 символов и 40 слов ([квоты](https://aistudio.yandex.ru/en/docs/search-api/concepts/limits)). Биллинг идёт за запрос; пример цены для РФ — 488 ₽ за 1000 дневных синхронных запросов ([тариф](https://aistudio.yandex.ru/en/docs/search-api/pricing)).

[Vector Stores](https://yandex.cloud/en/docs/ai-studio/vectorStores/) доступны, но для маленького версионированного каталога добавляют синхронизацию удалённого индекса и платное хранение: индекс округляется до целого ГБ в день, поиск тарифицируется отдельно ([тариф AI Search](https://aistudio.yandex.ru/en/docs/ai-studio/pricing)). Поэтому эта версия использует локальный индекс на основе активного снимка, а облако — только для явно запрошенного веб-поиска. Фактические права, квоты и биллинг серверного аккаунта без обращения к нему не проверены; live-проверка после выпуска остаётся частью этапа 8.

## Проверки и границы

Новые backend-тесты покрывают отсутствие ответа, спорную спецификацию, смену версии, сравнение, отказ Yandex, вредоносный XML/фрагмент, чужой проект и переход диалога к неподтверждённому intake-черновику. Локальная HTTP-проверка маршрута подтверждает источник и отсутствие `run_id`. 22 профильных backend-теста, 93 frontend-теста, lint, production build проходят. В локальном Chrome с фиктивным API пройден путь «каталог → сравнение → отдельный веб-поиск → карточка → возврат к диалогу → подтверждённый черновик → форма расчёта» на 1280 и 390 px. Секреты в тестах не используются; live Yandex-запрос не выполнялся.

Исторические immutable runs и C05 не менялись. Серверная выкладка этого этапа не проводилась.
