## Что изменилось

Добавлен формат `project-workbook-v1`: «Версия», «Инструкция», «Объект»,
«Зоны», «Процессы», «Роли», «Экономика», «Паспорт». Записи содержат стабильные
коды, понятные названия, value/unit/status/source/notes. UNKNOWN сохраняется
пустым, DATA требует источника, ASSUMPTION остаётся предложением. Паспорт
содержит все 42/39/57 параметров склада/аэропорта/клиники. Обязательные строки
структуры сохраняются; неизвестные паспортные значения не блокируют
поддержанный расчёт, если его собственные входы заполнены.

Гостю доступна самостоятельная страница **«Шаблоны и загрузка данных»**
(`#templates`): три профиля, пустой XLSX, отдельный demo, совместимый CSV,
промпт TXT и копирование текста. Промпт задаёт по 2–3 вопроса, сохраняет
структуру/единицы, требует источники, запрещает выдумывать числа, цену,
парк, финансы и подтверждения; предусматривает CSV, если LLM не создаёт файл.
Внешняя LLM не вызывается сервисом для импорта.

Preview показывает ошибки с листом/строкой и действием, неизвестные входы,
источники, допущения и diff к ранее загруженной книге проекта. Preview не
пишет в БД. Diff также показывает текущие редактируемые поля Brain. Apply
сохраняет файл, новый import и новую версию Brain в одной
транзакции. Проверяются предыдущий import, digest профиля и digest файла:
устаревший preview не применяется. Неуспешный импорт оставляет прежний профиль.

Зоны, процессы, batch, график, роли без дублирования общего персонала,
gross-зарплаты, ограничения и экономика переносятся в текущую форму. Входы
книги подтверждаются отдельной кнопкой перед нормализацией. Экономические
числа предложены с источником/SHA и требуют отдельного подтверждения;
пять коммерческих условий всегда остаются снятыми после импорта.
Проставленный внешней LLM YES не становится подтверждением пользователя.

Brain хранит полную исходную книгу и предлагает значения поддержанных
складских процессов. Каждое подтверждение создаёт следующую версию.
Brain выбирает процесс по коду; повтор одного кода в нескольких зонах
рассчитывается через форму с отдельными process IDs. Это явно указано на
странице, полные записи остаются доступны. Неподдержанная операция не
подменяется перевозкой. Аэропорт/клиника получают полный паспорт и процессы,
а preview сообщает границу готового пути Brain/каталога; пригодность и
новые формулы относятся к последующим этапам.

Legacy CSV/XLSX-адаптер сохранён. Legacy XLSX читает только cached values
через `data_only=True`: организаторский файл содержит формулу площади
аэропорта, и её готовый кэш остаётся совместимым. Формулы не исполняются.
В новом workbook формулы запрещены на всех листах, включая текстовый CSV.
Макросы запрещены для обоих форматов XLSX; применяются ограничения 5 МБ
файла, 25 МБ распаковки, 1000 ZIP entries и 3000 строк нового листа.

## Неизменность истории

Desktop-проход сравнил все **77** ранее существовавшие synthetic runs и
**24** simulation artifacts; mobile — **85** и **25** соответственно.
Все поля строк, включая input/result/trace/ScenarioSpec snapshots и checksums,
совпали до/после. Старый PDF сохранил SHA-256
`63c3175756dbf2ddd11241e4515ab3586b071d0515129883d989f7ae4bce6273`.
Добавлялись только новые synthetic проекты/версии/расчёты/артефакты.

Все **30** файлов существующего `backup/` совпали с manifest от
26.09.2026 01:51:11 UTC по SHA и числу строк. Его 20 production runs и четыре
simulation artifacts не импортировались в тестовые БД и не изменялись.
Аудит, опубликованный каталог, registry/formula versions не правились.

Свидетельства: [desktop](assets/f2/evidence/desktop.json),
[mobile](assets/f2/evidence/mobile.json), [Excel](assets/f2/evidence/native-excel.json),
[гостевая страница](assets/f2/evidence/guest-desktop.png),
[preview](assets/f2/evidence/preview-desktop.png).

Для повторения подготовить отдельную пустую localhost БД `stage11_*`,
seed через `scripts/stage11_seed_disposable.py` и локальные backend/Vite.
Для backend задать `PROJECT_FILE_STORAGE_ROOT` в disposable каталоге.
Команды Windows CMD для browser gate:

```cmd
set F2_DATABASE_URL=postgresql://f1@127.0.0.1:5541/stage11_f1_browser
python scripts\browser_f2_acceptance.py
set F2_MOBILE=1
python scripts\browser_f2_acceptance.py
```

Скрипт отклоняет нелокальный адрес и имя БД вне `stage11_*`, использует только
синтетические учётные записи. Новый deploy, миграции и серверный бекап для F2
не требуются. **Следующий этап F3 — только после новой команды пользователя.**
