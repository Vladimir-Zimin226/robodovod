## Доступность production

Read-only SSH-проверка `robodovod` показала: checkout `/opt/robodovod` находится на `ae40e208509fe738840a6a1a120e8cd51366277f`; `git status --short` пуст. Это совпадает с исходным локальным `main`. Запросы через HTTPS с самого сервера вернули `/ready` = `{"status":"ready","database":"available"}` и `/api/catalog/status`: discovery `organizer-catalog-v4`, 187 моделей / 223 позиции; capacity `ACTIVE`, 21 модель / 24 позиции; legacy runtime `unavailable`.

Digest действующих образов, Alembic revision и активный economics route **не подтверждены**. Для Docker Compose серверный пользователь требует `sudo` с паролем (`sudo -n`: `a password is required`), а прямой доступ к Docker API запрещён. Локальная Windows HTTPS-проверка не получила HTTP-ответ из-за ошибки TLS-клиента; серверный HTTPS-запрос выполнен успешно. Никакого переключения или развёртывания не было.

Перед выпуском оператору необходимо получить через разрешённый `sudo` без вывода секретов: `docker compose ps`, теги или digest действующих образов, `alembic current` и `python -m economics_route_activation status` в backend-контейнере. Затем сопоставить их с release commit и выполнить резервное копирование по production runbook. Если действующие образы или БД отличаются от ожидаемого состояния, сначала составить отдельный план обновления.
