# Рободовод — отчёт реализации плана 17.10.2026

Исходный план: `robodovod-master-implementation-plan-2026-10-17.md`. Изменения сделаны в существующих frontend, backend и RobCraft. Рабочие расчётные формулы C11/C14/C18 не переписаны; новый контракт расходов применяется только к новым экономическим запускам v7.

## Пользовательский путь

- Пять шагов: **Объект → Работа → Роботы → Деньги → Результат**. Вход с главной, из гостевого примера и из сохранённого проекта использует существующий проект и расчёты.
- На главной три режима: ознакомиться, оценить свой объект, подготовить материалы. На шаге «Деньги» доступны базовая, углублённая и полная глубины; сервер отдельно сообщает фактически рассчитанные ветки.
- AI-подбор Brain и Roboexpert, а также разговорное моделирование процесса сняты с навигации. Старые данные доступны для чтения; внешние AI/web POST-методы возвращают 410. Детерминированные расчёты и сравнение каталога действуют.
- РД-помощник вызывается на любой странице, отвечает из локального версионированного справочника и предлагает переходы к нужному шагу. Вопросы не отправляются во внешнюю модель и не меняют проект.

## Экономика

- Контракт `economics-explicit-inputs-v7` добавляет отдельные `DELIVERY`, `COMMISSIONING`, `INTEGRATION`; прежнее поле внедрения используется как **прочие работы**, сумма 0 требует явного ввода. Для статусов суммы сохраняются источник и основание. `UNKNOWN` остаётся неизвестным.
- При пропуске статьи сохраняются известная сумма и список недостающего, но покупка и зависимое сравнение не получают NPV или окупаемость. При полном вводе расходы передаются существующим денежным формулам отдельными строками. Старые v1–v6 и сохранённые снимки остаются историческими.
- Статьи видны в результате, PDF, читаемом отчёте и табличном экспорте. Каталоговая цена отделена от коммерческих расходов и не объявляется офертой.

## 3D и показ

- `scripts/blender/generate_robcraft_assets.py` воспроизводимо экспортирует четыре классовые GLB-модели: паллетный AMR, погрузчик, уборочный робот и медицинскую тележку. Исходники и модели CC0; это иллюстрации классов, не паспортные модели поставщика. Проверены размер файла, число треугольников и метрические габариты.
- Собственный WebGL-рендерер RobCraft загружает статические GLB, группирует треугольники по материалу, применяет LOD по расстоянию и оставляет процедурную геометрию при ошибке загрузки. Есть выбор **Авто / Высокое / Экономное** и ограничение разрешения кадра. Потеря WebGL переключает встроенную симуляцию на 2D.
- Необязательный презентационный режим в гостевом примере и денежном результате показывает последовательность контекстных кадров, переключение A/B в демо, исходный идентификатор результата, деньги и ограничения; доступны пауза, переход по кадрам, выход и режим сниженной анимации. Сама 2D/3D-симуляция сохраняет свои управление временем и ручную камеру.

Повторная генерация ассетов из корня репозитория: `blender -b -P scripts/blender/generate_robcraft_assets.py`. Четыре GLB записываются в `robcraft/public/assets/robots/`.

## Развёртывание

Приложение готовится и развёртывается по `docs/PRODUCTION_DEPLOYMENT.md`. На существующей БД **не** запускайте повторно импорт каталога, activation или bootstrap без сверки статуса. На сервере применяйте только проверенный commit/tag после backup и изолированного smoke. Команды для существующего Compose:

Локальную проверку `docker compose config --quiet` удалось выполнить. Отдельная сборка frontend Docker-образа остановлена автоматической проверкой разрешений из-за лимита использования; результат сборки образа неизвестен. Production не обновлялся.

```bash
cd /opt/robodovod
C='sudo docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml'
$C config --quiet
$C ps
$C build backend frontend migrate
$C up -d db
$C run --rm migrate
$C up -d --wait backend frontend caddy
curl -fsS https://robodovod.ru/health
curl -fsS https://robodovod.ru/ready
```

Новый контракт v7 не требует миграции таблиц, но действующий `migrate` должен соответствовать проверенному commit. Подробный backup, активация пустой БД, smoke и откат описаны в production runbook.
