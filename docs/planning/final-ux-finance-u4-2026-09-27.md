# U4 — представление результатов и выгрузок

## Что сделано

- Обычные экраны мощности, частичной и полной экономики больше не показывают повторяющиеся блоки с UUID, ревизиями, шаблонными ID и кодами проверок. Допущения показаны коротким списком с пояснением и источником; полная трассировка остаётся в защищённом архиве `Snapshot.json` и диагностических данных. Для просмотра исходных условий есть действие «Изменить допущение и создать новый расчёт».
- Новый экономический run получает версию `production-economics-orchestrator-v4` и `result-presentation-v1`. Финансовые значения по-прежнему рассчитывает действующий v3 движок. Исторические v3 runs воспроизводятся через v3 и экспортируются прежним способом.
- Общая серверная таблица `_presentation_rows` берёт только сохранённый `comparison` и ведомости сценариев. Из неё формируются новый читаемый PDF, лист «Обзор» XLSX, подробная часть CSV и ZIP. Разделы: входы и источники, итоговые показатели baseline/покупки/RaaS, годовые потоки, CAPEX, расходы по статьям, чувствительность и ограничения. Парк и мощность остаются в сохранённом техническом результате и технических листах XLSX/ZIP; основной экран показывает их отдельно.
- Экран полного сравнения показывает годовые потоки и разовые вложения, форматирует суммы по русским разрядам и даёт горизонтальную прокрутку таблиц на телефоне. В обычном PDF суммы форматируются с разрядами; в CSV/XLSX остаются исходные десятичные строки для точной сверки.

## Проверки

- `backend/test_final_economics.py`: новый и старый export из одного расчёта 220 паллет/сутки, 120 м и типового склада. Сверены NPV, годовой поток и CAPEX в PDF, CSV, XLSX, ZIP; старый архив детерминирован и не получает новый лист.
- `backend/test_final_economics.py`, `backend/test_readable_report.py`, `backend/test_persistence_integration.py`: 18 passed, 19 skipped (PostgreSQL недоступен в этом окружении).
- Frontend: 137 passed; lint и build прошли. Сборка выдаёт лишь предупреждение о размере существующего общего чанка.

## Границы проверки

- Серверное имя проекта не сохранено в финансовом snapshot; UI показывает его из текущего проекта, а автономный PDF указывает дату и тип оценки. Для появления имени в воспроизводимом PDF понадобится отдельное сохранение имени в новом входном snapshot.
- Новый PDF и общий обзор отражают статьи расходов ровно в том составе, который сохранил движок. Если статья годового OPEX не записана отдельно в результате, отчёт не восстанавливает её из агрегата.
- Проверка A4 выполнена генерацией и извлечением текста PDF; ручная визуальная проверка всех страниц и браузерный снимок экранов результата ещё входят в U5.
- Production не обновлялся. Исторические runs, snapshots, checksums и simulation artifacts не изменялись.
