## Исправления при приёмке

- В тесте RobCraft препятствие стояло на самой точке передачи паллеты. Тестовый сценарий перенесён на проезд перед ней: реальный объезд проверен, физически заблокированная точка остаётся безопасной остановкой.
- Тест PDF ожидал прежний заголовок с техническим суффиксом `(RaaS)`; проверено действующее читаемое представление и обновлено ожидание «При аренде роботов». Числа и экспортные байты не менялись.
- Сквозной браузерный сценарий Brain выбирает расчётную модель по подписи поля, а не по порядковому номеру `select`.
- Приглушённый текст на тёмных карточках имел контраст около 4:1. Цвет `--text-muted` изменён на `#89979d`; фактическая проверка Chrome для даты карточки отчёта даёт не менее 4,5:1 на desktop и 390 px.
- Убраны синхронные сбросы состояния внутри React effects при смене проекта и расчёта; компоненты привязаны к ключам проекта/run. Исправлены зависимости хуков, ESLint проходит без предупреждений.
- У сохранённого полного результата две соседние секции использовали одинаковый React key, а карточки стадий 2D/3D не имели key. Ключи сделаны уникальными; повторный живой Chrome-прогон прошёл без предупреждений о ключах в консоли.
- Тест складской цепочки теперь явно проверяет, что замедление отбора или упаковки уменьшает выход последней смоделированной стадии. Общая паллетная мощность и денежный расчёт при этом не переписываются.

## Локальные маршруты

- На одноразовой PostgreSQL 17 и локальных backend/Vite в Chrome пройдены desktop и 390 px: новичок → ответ «Помощника по сервису» → переход к расчёту и Back; диалог Brain с 220 паллетами/сутки и 120 м без AI Studio → подтверждённый профиль → C11 → частичная экономика и PDF; дочерний профиль «что если» → новый run, прежний PDF неизменен; типовой склад → пять подтверждений → полная экономика и PDF.
- Реальная страница «Отчёты» показывает версии владельца и сравнивает их на desktop/390 px. Чужому аккаунту список проекта и PDF отвечают 404. Открытие и выгрузка не изменили checksums сохранённого run.
- PDF из API совпадает с PDF внутри ZIP. ZIP проходит CRC; manifest внутри равен API manifest; SHA‑256 каждого артефакта совпадает с manifest, а заголовок PDF и digest источника совпадают с сохранённым result snapshot. В извлечённом PDF есть разделы покупки и аренды.
- «Робоэксперт» в браузере показывает сравнение по активному каталогу и информационные позиции. Без ключей AI Studio/Search структурированное сравнение остаётся доступным, AI и веб-поиск явно сообщают о недоступности и не меняют run.
- Сохранённый полный результат из истории повторно открыл 2D и 3D на 390 px; проверены фокус клавиатурой, браузерный Back, отсутствие горизонтального переполнения и предупреждений React о ключах.
- Границы складской цепочки подтверждены backend-тестами: паллетная перевозка не включает отбор и упаковку в денежный эффект; исследовательские и информационные позиции не становятся расчётными; ресурс водителя, общий для приёмки и отгрузки, учитывается один раз; узкое место отбора или упаковки уменьшает выход последней стадии только в поддержанном многозвенном сценарии.

## Production после публикации

Production **не обновлялся и не проверялся** в этом этапе. После публикации из каталога проекта на сервере выполнить в **Windows CMD**:

```cmd
git rev-parse HEAD
docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml ps
curl.exe -fsS https://robodovod.ru/ready
curl.exe -I https://robodovod.ru/
curl.exe -fsS https://robodovod.ru/api/roboexpert/options
```

Сверить HEAD с опубликованным коммитом; у `db`, `backend`, `frontend` должен быть статус healthy, `caddy` — running, `/ready` — `{"status":"ready","database":"available"}`. Затем в обычном браузере по HTTPS пройти: помощник → моделирование → проект → расчёт → частичный/полный отчёт → 2D/3D → PDF/ZIP → история; на телефоне проверить меню и Back. Серверные бекапы для этой проверки не требуются.
