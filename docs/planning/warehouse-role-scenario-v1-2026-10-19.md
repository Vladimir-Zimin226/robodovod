# Расчёт склада по ролям, v1

Основной складской маршрут: общие данные объекта → выбор всех работающих ролей → кандидаты из всего активного каталога для каждой роли → единый результат. Зоны и операции не вводятся. Прежний процессный маршрут доступен отдельно для старых расчётов.

## Что рассчитывается

- Для каждой выбранной роли сервер просматривает каждую позицию опубликованного каталога. Кандидаты определяются по расчётному профилю, названию, заявленному применению и описанию. Совпадение текста — гипотеза для обследования, а не доказанная пригодность. Широкий тег «Сортировка грузов» сам по себе не делает систему хранения сортировщиком; голосовые и световые подсказки не засчитываются как автоматический отбор.
- Первый кандидат вне стадии RND назначается автоматически как предварительный вариант для проверки. Стадия пилотирования явно помечается. Пользователь может выбрать другой вариант или убрать робота из общего итога; исследовательские модели автоматически не назначаются.
- Потребный парк по роли: `ceil(суточный объём × доля роботизируемой работы / (выработка робота в час × часы смены × смены × доступность) × (1 + резерв))`.
- Если в каталоге есть подтверждённая производительность с подходящей физической единицей, используется она. Иначе сценарное допущение: один робот выполняет за смену объём одного сотрудника. Пользователь может заменить выработку для выбранной модели.
- Потенциальные ставки: `min(численность роли, роботизируемый суточный объём / выработка сотрудника за смену) × доля часов, переводимых в ставки`. Значение не означает автоматического сокращения штата.
- Если есть рублёвая цена или пользователь указал сценарную цену, считаются парк × цена, доля внедрения, ежегодный сервис, годовой денежный эффект и NPV по заданным горизонту и ставке. Без цены денежный результат остаётся частичным.
- Итог суммирует выбранные назначения по уникальным ролям. Один и тот же артикул, назначенный двум ролям, означает отдельный парк для каждой; совместная загрузка роботов не предполагается без данных.

## Источники и ограничения

Типовые численность, расходы работодателя, объём работы и роботизируемая доля берутся из `frontend/src/roleWorkScenarioData.json`. Все они показаны пользователю как редактируемые сценарные допущения. Упаковщик в шаблоне означает работу в паллетах, поэтому кандидаты по коробочной упаковке не рассчитываются автоматически в паллетах. Пригодность манипулятора для паллетизации требуется подтвердить на объекте.

Каталог содержит разные предложения одного робота; они остаются отдельными позициями с собственными ценами и строками источника. Исследовательские модели отображаются, но помечаются отдельно. Общий сценарный NPV не является заключением о закупке: не хватает обследования маршрутов, нагрузок, расписания, интеграции и подтверждённой цены для всех вариантов.

В актуальном каталоге кандидат для комплектовщика Ronavi M подаёт стеллажи к станции комплектации и находится на стадии пилотирования. Он автоматизирует подвоз, а сам отбор остаётся за человеком; заданная доля роботизируемой работы должна отражать именно экономию времени на подвозе. «Робот-комплектовщик» показан отдельно как модель RND. Для сортировщика прямое описание работы есть у Ronavi SR/SD. Эти различия нельзя скрывать за общим процентом замены персонала.

Для оператора погрузчика и грузчика транспортный профиль каталога принимается лишь при указании работы с паллетами; робот для лёгких коробок не подставляется под паллетный поток. Для грузчика расчёт относится к перемещению паллет, а погрузка и разгрузка остаются ручными.

При редактировании данных во время предварительного расчёта старый ответ игнорируется. Заполненный до выбора проекта черновик временно сохраняется в сессии браузера, чтобы не потеряться при входе или создании проекта; после успешного сохранения в проекте он удаляется.

Сценарии сохраняются версиями в `project.profile.warehouse_role_scenarios_v1`; запросы привязаны к владельцу проекта. Версия результата содержит снимки входов и результата, идентификатор версии каталога и контрольные суммы. Существующие `analysis_runs` и старые результаты не изменяются.
