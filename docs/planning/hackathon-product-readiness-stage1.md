# Этап 1: читаемые числа и отчёты по типу результата

Выполнено 25 сентября 2026 года по плану
`hackathon-product-readiness-2026-09-25.md`.

- Экран C11 показывает парк целым числом и по-русски, производительность с максимум двумя знаками, покрытие и загрузку в процентах с определениями. Форматирование происходит только при отображении Decimal-строк.
- Денежные показатели на экране и в PDF округляются до копеек для чтения. Исходные значения, snapshots, CSV и проверки SHA-256 сохраняют полную точность.
- Читаемый PDF имеет отдельное содержание для C11, частичного и полного economics run. C11 сообщает техническую мощность и необходимые входы для следующего расчёта. Частичный отчёт перечисляет рассчитанные ветки, пропущенные поля и следующий шаг. Полный отчёт сравнивает baseline, покупку и RaaS. Исторический формат получает краткий отчёт и предупреждение для C16 v1.
- ZIP обозначает вид результата и исходный C11 run. Экспорт PDF/ZIP частичного результата доступен в интерфейсе. Экономические экраны показывают связь с исходным C11.
- Обновлён golden manifest ZIP v2 из-за нового текста PDF и инструкции. Машинные CSV и сохранённые run checksums не менялись.

Проверка: `backend/test_readable_report.py` и `backend/test_evidence_export_v2.py` — 12 passed; `npm.cmd test` — 97 passed; `npm.cmd run lint` и `npm.cmd run build` — успешно. Тест PDF проверяет строки `15 роботов`, `196,64 ед./ч`, `137,65 ед./ч`, `100 %`, `99,07 %` и исходное точное Decimal-значение в snapshot. Тест ZIP проверяет исходное NPV без округления и связь с C11.

Ограничение: этот этап не добавляет отсутствующие коммерческие входы и не строит 2D для частичного run. Для существующих runs нужен новый расчёт после заполнения данных; исторические snapshots не переписываются.
