# Этап 7 · архив доказательств, который можно открыть без инструктора

Локальная реализация 25 сентября 2026 года. Новый ZIP использует
`calculation-evidence-export-manifest-v2`, policy/generator v2.
`НАЧНИТЕ_ЗДЕСЬ.md` лежит в корне и связывает номер run, дату, версии расчёта,
SHA-256 сохранённого результата и `manifest.json`. Главный документ —
`Отчёт_Рободовод.pdf`: тот же читаемый русский PDF, что скачивается отдельно
через `report.pdf`. Предыдущий машинный PDF доступен под точным именем
`Технический_дамп.pdf` как вторичный материал аудитора.

`Как_читать_разделы.md` описывает для каждого из `Inputs`, `Selection`,
`Scenarios`, `CashFlow`, `Sensitivity`, `Sources`, `Trace`,
`Simulation`, `Versions` и `Snapshot.json`: что проверяет файл, какие
поля смотреть, откуда взяты значения и сколько записей в run. Все девять
CSV, полный `Snapshot.json` и машиночитаемый `manifest.json` сохранены.

`NOT_AVAILABLE` означает отсутствие раздела в сохранённом снимке: CSV
содержит только строку-заглушку, `record_count=0`. Это не ноль, не сбой
и не подтверждённый факт. Раздел `Simulation` отражает C23 report только
если тот уже является частью снимка run. Поздние C23 artifacts добавляются
отдельно по `request_id` и не меняют этот воспроизводимый ZIP. Ввод и
вычисление с версионированными SHA-256 доказывают целостность расчёта;
паспортные характеристики, доступность, цену и комплект поставщика
подтверждает отдельный источник. Сценарные допущения не повышаются до
vendor facts.

Новый manifest включает SHA-256 каждого файла кроме самого
`manifest.json`; для него применяется `manifest_digest` — SHA-256
канонического JSON с нулевым значением self-digest. Дополнительно manifest
содержит digest исходных immutable снимков, run/project ID, версии и при
наличии связанного C11 — его run ID и digest снимков. В этом случае архив
включает и `C11_Snapshot.json`, чтобы проверить числа из связанного
технического расчёта без обращения к серверу. Архив создаётся
с фиксированным порядком файлов и ZIP timestamp. Проверка исходных
снимков выполняется до сериализации. Формат v1 и его golden fixture
сохранены без изменений.

## Проверки

- Backend: golden v1/v2, одинаковый ZIP для того же run, все SHA-256,
  self-digest manifest, PDF внутри ZIP равен отдельному PDF, linked C11
  проверен, подмена связанного снимка отклонена, `NOT_AVAILABLE` и
  частичная покупка без ложного RaaS/NPV, русские тексты в PDF.
- ZIP: `testzip()`, полная распаковка и чтение кириллических имён файлов
  из временного каталога Windows.
- Frontend: строгий manifest v1/v2, привязка проекта/run/digest, русское
  имя архива, сохранение через browser API.
- Headless Chrome локально скачал точный ZIP по same-origin HTTP через
  `EvidenceExportSession`; имя файла на Windows и байты архива совпали,
  содержимое распаковано. Временный скрипт лежит только в ignored `.tmp`.

Серверный выпуск и полный PostgreSQL/browser регрессионный путь относятся
к этапу 8; исторические immutable runs не изменялись.
