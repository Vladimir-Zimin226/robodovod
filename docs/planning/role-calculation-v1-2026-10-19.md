# Расчёт труда по ролям: правила новых расчётов

Для каждой роли из `process.role_refs` новый денежный ввод сохраняет отдельную модель: долю заменяемой работы, ручную выработку в единицах процесса за смену, остаточные операции, источник и основание. Положительная доля требует отдельной выработки этой роли. Сервер отклоняет неполный или дублирующий набор ролей и не подменяет выработку одной роли выработкой другой.

## Явные проектные допущения

- Основная роль использует введённую пользователем долю работы и выработку. Если эти значения получены не замером, результат помечен как проектное допущение.
- Дополнительная роль по умолчанию получает долю **0**: вся её работа сохраняется, экономия по зарплате равна нулю. Это консервативное допущение, а не вывод из датасета. Пользователь может задать положительную долю и отдельную выработку.
- Для нулевой доли потребность роли принимается равной распределённому исходному штату. Ручная выработка не выдумывается. При положительной доле потребность рассчитывается из объёма процесса и выработки конкретной роли.
- Один рассчитанный парк роботов используется всеми ролями процесса. Парк, пульт и техническое обслуживание не умножаются на число ролей.
- Высвобождение ограничено штатом роли, покрытием парка, долей заменяемой работы и принятой кадровой схемой. Сотрудники, переведённые на пульт или техподдержку, не считаются высвобожденными.

Датасет организаторов содержит численность и некоторые показатели выработки, но не содержит замеров доли задач и отдельной выработки для каждой роли во всех процессах. До замера эти параметры остаются сценарными допущениями. Менять допущения следует новым расчётом от сохранённого C11; исторические результаты не переписываются.
