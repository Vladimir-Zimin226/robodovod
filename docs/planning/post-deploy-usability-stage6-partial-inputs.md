# Этап 6 · неполные данные без ложной экономики

Локальная реализация 25 сентября 2026 года. Новый ввод `economics-explicit-inputs-v2` сохраняется как `economics-run-input-v3`. Если данных недостаточно, результат имеет версию `economics-partial-result-v1`, с шестью явными статусами сценариев, причинами и списком полей для следующего шага. Полный набор данных использует прежний вычислитель C13–C21; входы v1 и старые снимки не переписываются. Экономический run остаётся неизменяемым, исправление ввода создаёт новый run от сохранённого C11.

## Матрица полей

| Вход | Единица и смысл | Для технической C03/C11 | Для C14 / покупки / RaaS | Пусто и 0 | Диапазон / источник |
|---|---|---|---|---|---|
| C03 активный процесс, объём, смены, часы, дни | единиц/сут, смен/сут, ч/смену, дней/год | Обязательны для C11; C03 не принимает неполный технический процесс | Повторно используются в C14–C17 | Пусто и 0 блокируют технический расчёт | Из процесса; пользовательский ввод или подтверждённый типовой объект |
| C03 плечо / партия / время обмена | м, единиц/рейс, сек. | Обязательны только для соответствующего профиля C11 | Влияют на парк и все финансовые ветки | Пусто останавливает нужную формулу; 0 не подставляется | Замер или явно отмеченный demo-сценарий |
| C03 численность роли | чел. | Для связанного role pool; положительное целое | C14 оценивает высвобождение | Пусто блокирует роль; 0 не означает существующую роль | Штатное расписание |
| C03 зарплата роли monthly gross | ₽/чел./мес. | Для технического C11 может быть UNKNOWN | Обязательна для C14, покупки и RaaS | Пусто = UNKNOWN; 0 допустим с `ZERO_COST_ROLE` | ФОТ или подтверждённое пользователем допущение; legacy `fte_cost_rub` не преобразуется |
| C11 модель, позиция и исполнение C05 | immutable catalog/run и статусы | Нужен сохранённый C11 для экономики | C05 `NEEDS_VALIDATION` не становится `PASS` | Нет C11 — экономика недоступна | Только серверный сохранённый run |
| C13 дата и горизонт | дата, 5–15 лет | Не нужны | Для покупки и сравнителя RaaS | Пусто = экономическая ветка не рассчитана | План проекта / пользовательская оценка |
| C13 ставка дисконтирования | доля 0…1 | Не нужна | Для NPV покупки и RaaS | Пусто = NPV не рассчитано; 0 допустимо осознанно | Финансовая политика / допущение |
| C14 основная роль, ручная производительность | роль, ед./смену | Не нужны для C11; производительность не нужна уборке | Для C14 и обеих финансовых веток | Пусто = C14/NPV не рассчитаны | Замер, норматив или допущение |
| C14 диспетчеры и техники | чел., ₽/чел./мес. gross | Не нужны | Для C14 и обеих финансовых веток | Пусто = не рассчитано; 0 = известный ноль | Штат и ФОТ / допущение |
| C15 цена организаторов и её RUB трактовка | ₽/робот | Не нужна для C11 | Для покупки и RaaS сравнителя | Нет цены / неподтверждённая валюта = не рассчитано | Каталог + явное пользовательское допущение; не оферта |
| C15 внедрение, сервис, гарантия, мощность | ₽ gross, ₽/робот/год, лет, Вт | Не нужны | Для покупки и RaaS сравнителя | Пусто = не рассчитано; денежный 0 допустим, мощность должна быть >0 | Смета, условия, паспорт или допущение; не подтверждение поставщика |
| C15 начальная батарея и замены | подтверждение включения | Не нужны | Для покупки и RaaS сравнителя | Нет подтверждения = ветка не рассчитана | Только явное сценарное подтверждение |
| C18 общие CAPEX/OPEX | ₽ gross всего / ₽ gross в год | Не нужны | Для покупки и RaaS сравнителя | Пусто = не рассчитано; 0 = известное отсутствие расходов | Смета / бюджет / допущение |
| C17 тариф, срок и плательщик инфраструктуры RaaS | ₽/робот/мес., мес., сторона | Не нужны | Только RaaS, после доступного покупного сравнения | Пусто = RaaS не рассчитан; 0 тариф требует осознанного ввода | Договор или допущение |
| C17 состав RaaS | явное подтверждение | Не нужен | Только RaaS | Пусто = RaaS не рассчитан | Пользовательское сценарное допущение; не vendor fact |
| C19–C21 время начала и часовой пояс | сек. от 00:00, IANA | Не нужны | Для полного сценария визуализации | Пусто = ScenarioSpec не рассчитан | График работы |

Правило веток: C11 показывается из сохранённого источника; C14 рассчитывается только при достаточных трудовых входах; покупка требует C14 и собственные расходы; RaaS требует сравнитель покупки и свой тариф/договор. Никакое неизвестное значение не заменяется нулём. Шесть сценариев имеют отдельные статусы и `required_fields`; отсутствующий NPV — `null`. Отрицательные значения и единицы вроде «100 kW» в поле «Вт» дают структурированную ошибку и не запускают соответствующую ветку. Денежный или иной десятичный диапазон в форме `500000..800000` сохраняется в `input_ranges` как пользовательская оценка, но не подменяется средним числом в формуле.

Форма показывает единицу, зачем поле нужно, пример, источник и различие пустого и нуля. Поля C03 для технической допустимости показывают локальные ошибки; C03 salary может остаться пустой. Результат показывает статус ветки, следующий шаг и сохранённые значения; повторное открытие run использует тот же снимок. C05 и procurement остаются видимыми как непроверенные, финансовая ветка не выдаёт рекомендацию к закупке.

Тест PostgreSQL API на create → reopen → replay добавлен в `backend/test_persistence_integration.py`; локально не запускался без `TEST_DATABASE_URL` к одноразовой базе.
