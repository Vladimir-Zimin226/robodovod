# P3 — ручная выработка одного сотрудника

27.09.2026. Поле подписано выбранной ролью и процессом; рядом показаны объём,
смены, длительность смены, плечо и влияние на F08/F09 и ФОТ. Новый read-only
API для сохранённого C11 возвращает оценку действующего C14/F08 с формулой,
единицей, значениями реестра и ссылками на источник. Endpoint проверяет
владельца, тип run и digest входа/результата; сохранённый C11 не изменяет.

Оценка не заполняет поле молча. Кнопка переносит точное число как
неподтверждённое допущение; отдельное подтверждение и его происхождение
сохраняются в новом экономическом run. Измеренная норма остаётся вводом
пользователя. При смене роли норма очищается; новый C11 после смены плеча или
смены перемонтирует форму. Ноль недопустим, пусто остаётся неизвестным.
Уборка показывает отдельную механизированную базу; для процесса без нормы
реестра оценка не предлагается.

Сверка по F08 для паллетного маршрута 120 м, 11 ч и двух смен:
`86,4 паллеты/чел./смену` одинаково при 220 и 2 000 паллет/сутки, поскольку
объём влияет на F09, а не на производительность одного человека. При 60 м
получается `135,771428…`, при 8 ч — `69,818181…`. Демо `100` остаётся
отдельным сценарием, а не автоматически измеренной нормой.

Проверки: 2 новых backend unit и 42 backend partial теста прошли; 11 frontend
targeted тестов, lint/build прошли. Интеграционный тест read-only API добавлен
к PostgreSQL gate, но не запускался без одноразовой БД. Браузер desktop/mobile
проверяется в P6. Точные нормы объекта и квалификация роли остаются входом
пользователя.
