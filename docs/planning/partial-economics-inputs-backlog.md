# Backlog: частичный C13–C21 при неизвестных коммерческих условиях

Статус: **BACKLOG, не реализовано**. После первого живого C11 пользователь
получает длинную форму C13–C21. Контракт `economics-explicit-inputs-v1` сейчас
требует даже те поля, для которых нет подтверждённых условий. Ввод нуля ради
прохождения формы нельзя выдавать за факт отсутствия затрат.

## Задача

Спроектировать versioned partial-input contract и серверный partial result:

- Каждое коммерческое и кадровое поле получает `KNOWN` / `UNKNOWN` / `NOT_APPLICABLE`
  с единицей, provenance и причиной неизвестности; **пустое не равно нулю**.
- Выполнять доступные C11, C14 и независимые части C13–C21; зависимые NPV,
  payback, ranking и procurement отмечать `INCOMPLETE` с точными missing refs.
- Purchase и RaaS должны деградировать независимо: отсутствие RaaS-тарифа
  не скрывает рассчитанный purchase и наоборот. Неизвестные warranty,
  battery, power, integration и shared costs не заменять скрытыми defaults.
- Отдельно разрешить C23/2D/3D из валидного C11/ScenarioSpec без требования
  заполнить финансовую форму; не выдавать отсутствие SLA/ресурсных данных за PASS.
- Не выводить monthly gross из legacy `fte_cost`, не подтверждать RUB/состав
  поставки от имени пользователя и не поднимать demo C05 до PASS.
- Сохранить immutable snapshot, versioned viewer/export, tenant/CSRF gates и
  deterministic replay. Исторические v1 runs не переписывать.

Приёмка: матрица missing/known/zero для каждой ветви, golden и API/persistence
регрессии, UX-тест явного перечня пробелов, повторное открытие и экспорт
partial run. До принятия этого контракта полная форма остаётся обязательной;
демонстрационные значения допустимы только как явно отмеченные сценарные
допущения, не как подтверждённая закупочная информация.
