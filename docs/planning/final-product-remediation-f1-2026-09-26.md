# F1 — связь расчёта, физического сценария и симуляции

F1 принят локально 26.09.2026. Основание — коммит аудита/плана `03741d5`.
Все критерии F1 проверены; F2 не начат. Production не обновлялся.

## Результат

Селектор «Физический сценарий проекта» открывает поддержанные сохранённые
FULL_ANALYSIS версии владельца: как технические/частичные, так и полные.
Внутри версии доступны сохранённые отчёты паллетной перевозки и складской
цепочки. Каждый выбор загружает свой run, точный ScenarioSpec и C23; состояние
проигрывателя и 3D сбрасывается. Покупка/аренда и финансовая неопределённость
отдельно объяснены как денежные варианты общей основы PURCHASE/BASE.
Переключение физической версии не изменяет денежную таблицу исходного run.

На экране показаны исходный C11, выбранный FULL_ANALYSIS, процесс,
model/position, спрос, плечо, batch, обмен, парк, nominal/effective capacity,
окна работы, timezone и модельное начало. Прежние финансовые результаты
и snapshots не пересчитываются при просмотре. Изменение физических входов
сохраняется отдельными C11 и FULL_ANALYSIS; новые физические классы не добавлены.

В 2D видны зоны, стеллажи, точки передачи/выгрузки, направление потока,
роботы и условная зарядная точка ↯. Она иллюстрирует агрегированное допущение
о простое: координаты, зарядный цикл и движение не являются измерением.
CONSISTENT обозначает согласованность модели и не подтверждает пригодность
к внедрению. Недовыполнение/перегрузка имеют отдельное объяснение и KPI очереди.

Кнопка «Сохранить открытый 2D-кадр · SVG» сохраняет именно текущую зону,
кадр и серверный отчёт; CSS переносится внутрь SVG. Файл содержит подпись,
дату, физические входы, основные KPI, run/C11/revision/report IDs и digests.
Metadata `simulation-visual-export-v1` сохраняет точные request/report,
время кадра и зону. Его можно использовать в пакете F5 без нового расчёта.
Включение изображения в общий ZIP/PDF остаётся работой F5.

При смене проекта очищаются старые result/input/run. В частичном результате
и Brain компоненты привязаны к отдельным run keys. При смене сценария
поздний ответ прежнего запроса не применяется; 3D получает новую пару
ScenarioSpec/C23 и общую временную шкалу.

  `browser_f1_acceptance.py` прошли; последний включает обе ширины, API
  негативные проверки, новые версии, SVG, общий 3D payload, reset/reopen.
- Ruff затронутых Python файлов и `git diff --check` прошли.
- Все **30** файлов существующего `backup/` совпали с первоначальным
  manifest от 26.09.2026 01:51:11 UTC по SHA-256/числу строк. Исторические
  20 runs и 4 simulation artifacts не импортировались в тестовую БД и не менялись.
  Принятые contracts/fixtures, registry/formula versions и каталог не правились.

Проверки запускались с отдельной локальной PostgreSQL 17 на порту 5541,
БД `f1_tests` и `stage11_f1_browser`, backend/Vite на localhost.
YC был отключён; F1 не требует внешних запросов. Полный suite всех подсистем
и production acceptance относятся к F8; здесь пройдены все targeted gates F1.

Для повторения browser gate сначала подготовить пустую disposable БД с
`scripts/stage11_seed_disposable.py`, запустить localhost backend/Vite,
затем в Windows CMD:

```cmd
python scripts\browser_stage31_brain.py
set F1_DATABASE_URL=postgresql://f1@127.0.0.1:5541/stage11_f1_browser
python scripts\browser_f1_acceptance.py
```

Адрес БД заменить адресом созданной локальной disposable БД. Скрипт
отказывает для нелокального host или имени вне `stage11_*`. Он создаёт
только новые synthetic версии; результаты проверки пишет в `.tmp/f1/`.
