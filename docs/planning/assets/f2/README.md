# F2: синтетические входы, а не данные заказчика

Формат: `project-workbook-v1`. Пустые книги и CSV содержат UNKNOWN вместо
нулей. Demo содержит организаторский паспорт и сценарные числа со статусом
ASSUMPTION. Книги генерирует `scripts/build_f2_examples.py`.

`interview-220-120.xlsx` — результат синтетического интервью по промпту:

| Группа вопросов | Синтетический ответ |
|---|---|
| Какой объект? Какая зона и ограничения? | Склад, основная зона; проход 3 м, ровный пол, груз 800 кг; обследование не выполнено |
| Каков поток? Какое плечо и batch? | 220 паллет/сутки; 120 м в одну сторону; 2 паллеты за рейс |
| Какой обмен? Какой график? | 90 с за рейс; 2 смены по 11 ч; 365 дней/год |
| Какие роли и gross зарплата? | Одна общая роль оператора погрузчика, 25 человек, 120000 ₽/чел./месяц до удержаний |
| Какие экономические предложения и источники? | Учебные значения из листа «Экономика», источник явно синтетический; пять YES являются предложениями, а не подтверждением пользователя |

Паспорт в этом примере остаётся организаторским ASSUMPTION. Указанный batch
проверяет сохранность входа; пригодность оборудования под такой груз требует
отдельного обследования и не доказывается этим предварительным расчётом.
LLM не вычисляет парк или финансы и не подтверждает входы в сервисе.

`typical-warehouse.xlsx` — 2000 паллет/сутки, 120 м, batch 1, тот же график,
роль и предложения экономики. Все заполненные значения помечены ASSUMPTION.
Оба файла проверяют один и тот же механизм подтверждения; USER_CONFIRMATION
в книге отсутствует. `normalized-examples.json` — серверная нормализация этих
двух файлов для frontend regression, с происхождением и SHA фактической книги.

`evidence/` содержит результаты Chrome desktop/mobile, native Excel и
скриншоты. Пользователи и UUID в них созданы исключительно для localhost
acceptance. Полные сравнения C11 и подробные логи остаются в `.tmp/f2/`.
