# Этап 7: публичное демо паллетной перевозки

Локальная реализация от 26 сентября 2026 года. Следующий этап не начат.

## Результат

- Гостевая страница называется «Паллетная перевозка на типовом складе» и показывает расчёт C11, шесть сохранённых денежных сценариев, чувствительность, охват складской цепочки и общий сохранённый отчёт симуляции во вкладках 2D/3D. PDF и ZIP доступны по публичным статическим ссылкам без регистрации.
- Источник один: авторский сценарий `warehouse-economics-demo-v1` и offline захват движков `scripts/build_warehouse_guest_demo.py`. Профиль содержит 2 000 паллет/сутки, две смены по 11 часов, маршрут 120 м, обмен 90 с; C11 даёт парк 18. Симуляция того же `ScenarioSpec` завершает 1 989 из 2 000 заданий до конца окна. Разница видна в отчёте и не скрывается.
- Пакет `warehouse-pallet-demo-v1` создаётся `scripts/build_warehouse_guest_package.py`. При сборке проверяются версии и digest входа, результата экономики, ScenarioSpec, запроса и отчёта симуляции, а также численность парка, поток и маршрут. `manifest.json` содержит SHA‑256 каждого вложения. ZIP включает manifest, PDF, полный JSON пакета, допущения, запрос и отчёт симуляции. PDF содержит те же шесть NPV, baseline, чувствительность, допущения, статусы и ограничения.
- Страница явно отделяет перевозку и труд водителя погрузчика от отбора, передачи тары, упаковки и паллетизации. Для остальных операций статус «Не рассчитано»; их труд не включён в денежный эффект. Геометрия 2D/3D названа условной. C05 остаётся `NEEDS_VALIDATION`, закупка `UNVERIFIED`.
- Демо целиком собирается из авторских тестовых данных и не читает пользовательскую БД, не открывает чужой run и не создаёт гостевой run в production. Публичные идентификаторы — фиктивные `tenant.demo` и `00000000-0000-0000-0000-000000000041`.
- Карточки демо приведены к тёмной палитре приложения; для ширины до 720 px блоки и таблица адаптируются к телефону.

## Проверки

- `python scripts/build_warehouse_guest_package.py --check` — пройдено.
- `python scripts/build_warehouse_guest_demo.py --check` — пройдено; старый захват не изменён.
- `python -m pytest backend/test_warehouse_guest_package.py backend/test_simulation_stage6.py backend/test_economics_orchestrator.py -q` — 20 passed. Проверены идентичность PDF/ZIP/страницы, manifest SHA‑256, читаемость русского PDF, все шесть NPV, baseline, чувствительность, ограничения и фиктивные идентификаторы. Регрессия 220 паллет/сутки и 120 м входит в `test_simulation_stage6.py`.
- Ruff `E4,E7,E9,F` для изменённых Python файлов — пройдено. JSX разобран локальным Babel parser без ошибок.
- Полный Node/Vite/frontend browser gate в текущей sandbox недоступен: Node при запуске файлов выдаёт `EPERM lstat C:\Users\Владимир Королев`. Поэтому фактический вид на desktop/телефоне требует проверки в среде с доступом к каталогу пользователя. PostgreSQL не нужен для статического демо.

## Публикация и статус

Публичные файлы лежат в `frontend/public/demo/warehouse-pallet-v1/`. При сборке frontend Vite должен скопировать их как статические assets; после выпуска следует проверить HTTP 200 и типы `application/pdf` / `application/zip`, открыть вкладки 2D/3D на desktop и телефоне, скачать оба файла без входа.

Исторические immutable runs и их снимки не изменялись. Отдельный коммит в этой sandbox не создан: `.git` доступен только для чтения, а рабочее дерево уже содержит незакоммиченные изменения этапов 3.1–6. Эта доработка ограничена этапом 7; этап 8 ожидает следующего сообщения пользователя.
