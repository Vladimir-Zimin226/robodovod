# РобКрафт MVP

Автономный браузерный движок процедурной сценарной симуляции и редактирования объектов. Самостоятельный runtime не использует код, зависимости или API основного приложения РОБОДОВОД; embedded-режим связывается с ним только через публичный ScenarioSpec и оконный протокол.

## Возможности

- четыре режима: автоматический показ, симуляция от первого лица, свободная камера и редактор строительства;
- автоматический режим `AUTOPILOT` по умолчанию: непрерывные общие, маршрутные, операционные и событийные планы без pointer lock;
- первое маршрутное задание запускается сразу, а общие планы используют плавное движение камеры;
- выбор стен, составных стеллажей, оборудования и роботов непосредственно прицелом в 3D;
- подсветка объекта под прицелом, жёлтая рамка выделения и карточка свойств;
- перемещение по X/Z и высоте, поворот и изменение размеров;
- настраиваемая сетка 0,25/0,5/1/2 м с возможностью отключения;
- строительство стен, стеллажей, паллет и грузов, рабочих станций, зарядок, ограждений и декоративных блоков;
- полупрозрачный зелёный/красный предпросмотр с запретом пересечения твёрдых объектов;
- удаление, дублирование и история Undo/Redo минимум на 20 действий;
- выбор робота, замена совместимой модели, изменение старта, зарядки и добавление маршрутных точек;
- версионированный `robcraft-scene-patch-v1`: базовый seed/config отделён от пользовательских изменений;
- экспорт и импорт редактируемой сцены в JSON, сброс к процедурной базе с подтверждением;
- немедленное обновление renderer и коллизий; симуляция в редакторе автоматически ставится на паузу;
- объёмное полусферическое освещение, материальные блики, мягкая тональная коррекция и атмосферный туман;
- полупрозрачное стекло и контактные тени под оборудованием, роботами и людьми;
- детализированные процедурные модели построенных стеллажей, станций, зарядок, грузов, ограждений и декоративных блоков;

- воспроизводимая генерация мира по текстовому seed;
- локальное преобразование описания собственника в спецификацию мира;
- распознавание типа объекта, габаритов, числа роботов, планировочных единиц и загрузки;
- прозрачный список распознанных значений, допущений и ограничений диапазона;
- физический корпус AMR с непрерывной проверкой стен, оборудования и других роботов;

## Запуск

Из корня репозитория:

```powershell
node .\robcraft\server.mjs
```

Открыть в браузере <http://127.0.0.1:4174>.

Альтернативно из папки `robcraft`:

```powershell
npm.cmd run dev
```

Порт можно изменить переменной `ROBCRAFT_PORT`:

```powershell
$env:ROBCRAFT_PORT=4180
node .\robcraft\server.mjs
```

## Управление

- без действий пользователя работает непрерывный автопоказ;
- клик по сцене — принять ручное управление с текущей позиции;
- `Esc` — освободить мышь и вернуться к автопоказу без сброса симуляции;
- `W A S D` — движение;
- мышь — направление взгляда;
- `Shift` — ускорение;
- `F` — включить или выключить свободный полёт;
- `B` — включить или выключить редактор; при входе симуляция останавливается;
- `Tab` — включить или выключить аналитическое зрение;
- `Space` / `Ctrl` — подняться или опуститься в режиме полёта;
- `E` — открыть/закрыть карточку робота в центре взгляда;
- `E` также открывает роль и текущую задачу человека;
- `G` — вернуться к настройкам генерации вне редактора;
- клик по миру — снова захватить мышь.
- кнопка `ЗВУК` — включить или отключить окружение, шаги и сигналы.
- кнопка `ОТЧЁТ` — открыть текущие KPI и вывод симуляции;
- `ЭКСПОРТИРОВАТЬ JSON` — скачать конфигурацию и снимок телеметрии;
- `ПИК СПРОСА` / `СБОЙ AMR` — запустить управляемое событие сценария.

### Редактор

1. Нажмите `B`. Панель слева показывает каталог, активный инструмент, сетку и историю.
2. Наведите центральный прицел на объект и нажмите ЛКМ. Зелёная подсветка означает объект под прицелом, жёлтая рамка — выбранный объект.
3. Нажмите `G`, чтобы перемещать выбранный объект за прицелом по X/Z, затем ЛКМ для подтверждения. `X`, `Y` или `Z` выбирают одну ось, стрелки `↑`/`↓` двигают по ней с текущим шагом. `Esc` или ПКМ отменяет операцию.
4. `R` поворачивает на 90°. `[` и `]` уменьшают/увеличивают размер по X; с `Shift` — по Z, с `Alt` — по Y.
5. `Delete` удаляет, `Ctrl+D` дублирует, `Ctrl+Z`/`Ctrl+Y` выполняют Undo/Redo.
6. Для строительства выберите тип в каталоге. Зелёный предпросмотр можно подтвердить ЛКМ; красный означает конфликт коллизий.
7. Сетка и шаг меняются в панели. Снятый флажок «Сетка» даёт свободное позиционирование; удержание `Alt` временно отключает привязку предпросмотра.
8. У выбранного робота доступны совместимая модель, стартовая позиция, зарядная позиция и новая промежуточная маршрутная точка. Координата берётся из точки пола под прицелом.
9. Кнопки `JSON` экспортируют/импортируют документ сцены. «Сброс» после подтверждения удаляет весь ScenePatch и повторно применяет исходную генерацию.

Во время работы с панелью указатель свободен. После клика по 3D-миру браузер захватывает мышь для обзора и WASD; `Esc` снова освобождает её.

В embedded-режиме `/robcraft/?embedded=1` launcher скрыт, а движок автоматически
ждёт расчётный ScenarioSpec от родительского React-приложения.
Переключатель скорости ×1/×2/×4 остаётся доступным в левом нижнем углу.
Кнопка «Осмотреть вручную» включает pointer lock только после явного действия;
`Esc` возвращает непрерывный автопоказ. Если браузер отклонил pointer lock,
автопоказ не прерывается. После входа в ручной режим появляется отдельная команда
редактора. Она ставит симуляцию на паузу; выход продолжает изменённую сцену в
автопоказе, а сброс возвращает исходную расчётную геометрию.

Звуковая тема зависит от объекта: промышленная для склада, терминальная для аэропорта и спокойная приборная для больницы. Двигатель ближайшего AMR меняет тон вместе со скоростью.

## Контракты запуска

Расчётный warehouse-сценарий этапа B запускается через строгий адаптер:

```js
import { generateWorldFromScenarioSpec } from './src/world/generator.js';
import { createSimulation } from './src/simulation.js';

const scene = generateWorldFromScenarioSpec(scenarioSpec);
const simulation = createSimulation(scene);
```

Форма `scenarioSpec` определена в
`../contracts/scenario-spec-v1.schema.json`; воспроизводимый пример находится в
`../contracts/fixtures/scenario-spec-v1.golden.json`. Адаптер поддерживает несколько
зон и отдельные концептуальные сцены транспорта, клинической доставки, уборки и
паллетизации. Он отклоняет неизвестные поля/версию и висячие `zone_id`, создаёт
точное количество рассчитанной модели каждой зоны и использует `demand_per_day`,
`units_per_trip` и `exchange_time_s` в симуляции. Зоны без оборудования остаются
в списке с явным статусом. Экономически неприемлемая зона может визуализировать
реальный технический вариант, но сохраняет отрицательный статус и маркировку
«не рекомендация».

При нескольких поддержанных зонах автопоказ переключает их каждые 24 секунды.
Селектор позволяет выбрать сцену вручную; ручной осмотр сам зону не меняет.
ScenePatch привязан к `zone_id`. FloorplanUploader позволяет явно связать каждый
полигон с зоной, backend передаёт его в ScenarioSpec, а RobCraft показывает
масштабированный справочный контур. Сцены пока остаются концептуальными: единая
физическая модель здания с общими коридорами по плану не генерируется.

Основной UI встраивает движок по same-origin пути `/robcraft/`. Строгий протокол
`robcraft-message-v1` проверяет origin, источник окна, версию, тип, `revision_id`,
`request_id` и неизвестные поля. Смена выполняется в две фазы: движок сначала
отвечает `PREPARED`, а изменяет видимую сцену только после `APPLY_REVISION`, затем
подтверждает `APPLIED`. Неподдерживаемые зоны и процессы возвращают явную ошибку;
их 3D-поддержка относится к этапу G.

Этап E добавляет `SET_CAMERA_MODE` и `CAMERA_MODE_CHANGED`. Управление камерой
принимается только для активной ревизии. Embedded-инспектор `E` показывает робота,
человека, станцию или концептуальную зону, не останавливая симуляцию. Этап F
добавляет строгие `SET_EDITOR_MODE`, `EDITOR_MODE_CHANGED` и
`SCENE_PATCH_CHANGED`. Расчётный patch связан с `revision_id` и
`visual_fingerprint`; несовместимый импорт отклоняется, а UI и операционный отчёт
явно сообщают, что геометрия изменена без пересчёта экономики.

Прежний standalone-вход сохранён:

Движок строится из обычного объекта конфигурации:

```js
generateWorld({
  template: 'warehouse',
  seed: 'WAREHOUSE-42',
  width: 48,
  depth: 38,
  rackRows: 5,
  robotCount: 4,
  occupancy: 72
})
```

Поле `template` принимает `warehouse`, `airport` или `hospital`.

Для standalone-конфига сохранён предел 8 роботов. Контрактный warehouse-путь после
строгой валидации поддерживает до 100 машин и автоматически расширяет зарядную зону.

Seed отвечает за воспроизводимую базовую вариативность, а поля спецификации — за обязательные параметры объекта. Редактор не мутирует этот контракт: изменения находятся в `ScenePatch`, а JSON-документ хранит `base` и `scenePatch` раздельно. В расчётном режиме база patch содержит активные `revision_id` и `visual_fingerprint`.

## Граница MVP

Это интерактивная сценарная визуализация, а не инженерный цифровой двойник или CAD/BIM. Роботы выполняют задания базового диспетчера с логикой безопасности, грузовых операций и зарядки. Редактор использует блочную геометрию; нет точных размерных ручек мышью, многоуровневых объектов, инженерной оптимизации всего транспортного графа и safety-валидации. Локальный A* умеет объезжать препятствие в пределах текущего сегмента, но не пересчитывает глобально все технологические маршруты после произвольной перестройки здания.
